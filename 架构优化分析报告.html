💡 具体优化建议

P0-1: 拆分 db.py（预计节省 60% 维护成本）

按领域拆分为 6 个模块：

新文件职责预估行数
db/users.py用户增删改查、密码验证、资料~500行
db/config.py配置读写（app_config 表）~100行
db/uploads.py上传会话、文件管理~300行
db/activity.py活动日志、统计、搜索~400行
db/teams.py团队、协作、权限~400行
db/base.py连接管理、初始化、通用工具~200行
✅ 收益：每个文件职责单一，合并冲突减少 70%，新人上手时间缩短 50%

P0-2: 修复 SQL 注入风险

  • 将 23 处 f-string 拼接 SQL 全部改为参数化查询（? 占位符）
  • 动态表名/列名用白名单校验，不直接拼接到 SQL
  • 添加 SQL 检查脚本到 CI，禁止新的字符串拼接 SQL
✅ 收益：消除 SQL 注入风险，查询性能提升（预编译缓存）

P0-3: 重构 excel_analysis.js（161个全局变量 → 1个命名空间）

  • 用 IIFE 或 ES Module 包裹，只暴露必要的全局函数
  • 状态集中管理：const state = { currentAnalysisData, currentFileName, ... }
  • 按功能拆分为 3-4 个模块：文件上传、分析渲染、图表、邮件导出
✅ 收益：消除命名冲突，内存占用降低，可维护性大幅提升

P1-1: 抽取公共函数到 routes/common.py

  • _require_login、_current_user_id 等重复函数统一到 common.py
  • 统一错误处理、统一响应格式
  • collab.py 与 collab_v2.py 合并，废弃旧版本

P1-2: 拆分大路由文件

  • analysis.py 按子功能拆分：CR分析、日志分析、趋势分析
  • tools.py 按工具类型拆分：文档工具、研发工具、效率工具
